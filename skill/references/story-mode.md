# 故事模式

用整页照片讲演变、讲历史、讲「同一种形状一直都在」。
转场不只是衔接，**转场本身就是论据**：拨号盘推近切到镜头，观众自己就看出「圆一直都在」。

## 转场计划就是故事线

先想清楚这一期要推的**一个**论点（比如「屏幕越来越小，也越来越近」），
再找能把照片串起来的形状。每次翻页的「关系」连起来读，应该就是这一期的叙事：

```html
<!-- 转场计划（故事线：圆一直都在）
1→2  关系：拨号盘和镜头都是圆，同位置同大小    手法：推近匹配      锚点：dial → lens
2→3  关系：圆变成了屏幕                      手法：遮挡变形      锚点：lens → screen
-->
```

## 页面写法

```html
<section data-guide="dial" data-hold="2">
  <img class="st-photo" src="photos/photo-01.png" width="1536" height="1024"
       data-anchors="dial:642,522,122">
  <p class="t-body" style="left:120px; top:820px;">No.01</p>
  <p class="t-h1" style="left:120px; top:880px;">转盘电话</p>
</section>
```

- **一页一张照片**，`class="st-photo"`，**必须写原图的 `width` `height`**。照片自动铺满画布（多出的部分上下裁掉）。
- **`data-anchors`**：照片上可以用来匹配的区域，坐标是**原图像素**。多个用分号隔开。
  - 圆：`名字:中心x,中心y,半径`
  - 矩形：`名字:左上x,左上y,宽,高`（只用于在照片里是正的矩形）
  - 四边形：`名字:q:x1,y1,x2,y2,x3,y3,x4,y4`（四个角，顺时针或逆时针依次写）。
    **照片里斜着的、有透视的形状一律用四边形**（斜放的手机屏幕、侧面拍的卡片），用正矩形框不住。
  - 格式写错（数字个数不对、有非数字）会报错；半径小于 40 的锚点会警告。
    矩形和四边形的「半径」按外接框长边的一半算。
- **`data-guide="锚点名"`**：这一页的引导框（强调色描边）常驻在哪个锚点上。
  故事稿的每一页都要写，引导框就是观众视线的钉子。转场页的 `data-st-to` 要等于本页 `data-guide`，
  `data-st-from` 要等于上一页 `data-guide`，不一致会警告（引导框会跳）。
- 文字只放在左下角：编号 `.t-body` `left:120 top:820`，名称 `.t-h1` `left:120 top:880`（编号行框高 50，和名称之间留 10）。
  运行时会自动在底部加暗色渐变，保证文字可读。不要放更多文字。

## 两种手法

| 前后两张照片的关系 | 手法 | 写法 |
| --- | --- | --- |
| 两个锚点**形状相同**（圆对圆，方对方） | **推近匹配** | 目标页写 `data-st="zoom-match" data-st-from="上一页锚点" data-st-to="这一页锚点"` |
| 两个锚点**形状不同**（圆变成方） | **遮挡变形** | 目标页写 `data-st="iris" data-st-from="上一页锚点" data-st-to="这一页锚点"` |

两种写法里，`data-st-to` 通常就是这一页的 `data-guide`。

### 推近匹配（`zoom-match`）

镜头加速推近上一张照片，直到锚点到画面正中、半径 300px；就在这一帧切到下一张照片，
它的锚点也在正中、一样大，然后减速拉远。引导框全程套在锚点上。切点是整段运动最快的时候。

1. 两个锚点**形状要一样**：都是圆，或者都是矩形 / 四边形（一个圆一个方会警告，改用遮挡变形）。
   矩形对四边形可以，切点前后引导框会平滑地变过去；但两者外接框的长宽比（宽 ÷ 高）最好相差不到 0.3。
2. 运行时会自动处理两件事，不用自己算：
   - **不露边**：锚点不在照片中间时，切点不放在画面正中，而是挪到两张照片都能铺满画布的位置。
   - **不糊**：相对原位最多推近 3 倍。
3. 录制时出现这两条警告，就要换锚点或换顺序：
   - 「推近不够」：警告会写出两边各推近几倍，以及原因——要么某个锚点在照片里太大（比如整块屏幕），
     要么另一个锚点太小，推近上限把切点半径压低了。按原因换锚点（旋钮、按键、镜头这类中等大小的最好）。
   - 「推近后会露出照片边缘」：两个锚点在各自照片里的位置差太多（一个在最左，一个在最右）。
4. 锚点半径小于 40 的不要用。
5. 默认时长 1.8 秒（字幕淡入会让录制时长多出 0.1 到 0.2 秒），不要改短。

### 遮挡变形（`iris`）

引导框从上一张照片的锚点处填满颜色、放大到盖住整个画面；盖满时换照片；
再缩成下一张照片上锚点的形状（圆、矩形、四边形之间都能变），颜色褪掉只剩边框。

1. 用在形状变了的地方：圆 → 方，大 → 小。
2. 默认时长 1.4 秒。

## 规则

- 故事稿里**不用**汇报稿的手法（`transitions.md` 手法表里那些），也不用 `.s-*` 形状类。
- **同一个故事里，推近匹配至少占一半的翻页。** 它是故事模式最有说服力的手法。
- 连续两次遮挡变形会显得廉价，中间至少隔一次推近匹配。
- 照片和锚点坐标由用户提供，**不要自己猜坐标**。没有可用的锚点就告诉用户缺什么。
