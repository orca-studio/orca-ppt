# 经营数据汇报

手法：一张表做成汇报稿

## 参考拆解

参考的是年度经营汇报、财报发布会这一类稿子：用户手里是一份表格（`.xlsx`、`.numb`、`.csv`），
要的是一份**每个数都有出处**的汇报。好的这类稿子靠三样东西叠起来：

1. **数字是主角，单位退一档**：「1.21」用最大的字，「亿元」「%」小一号跟在后面。报表就是这么排的，
   也让三位数的百分比塞得进小格子。
2. **先总览，再逐个展开**：第一页之后马上给一页总览，把全年最重要的四五个数摆在一起；
   后面每一页都是总览里某一格的展开。
3. **出处写在稿子里**：数从表格的哪个范围来，写进转场计划注释、存进 `data/`，结尾页再写一遍。

本同款加的看点是**总览和细节是同一样东西**：

> 封面的深蓝整页收成总览里「全年营收」那一格；「季度营收」那一格展开成图表面板；
> 第四季度那根柱子拆成三个月；坐标轴长成渠道排行里最长的那一条；最后一块深蓝面板撑满整页收尾。

观众一路看到的是同一份数据被一层层打开，而不是一页页换图。

## 适用 / 不适用

| 适用 | 不适用 |
| --- | --- |
| 用户给了表格，要做年报、季报、经营复盘、项目数据汇报 | 没有数据，或者只有一两个数 —— 撑不起总览，用 `cobalt-grid` 或通用流程 |
| 有一组**随时间变化**的数（季度、月份），其中最后一段值得拆开看 | 数据都是并列概念、没有大小关系 —— 做成柱子读出来的高低是假的 |
| 有一组**构成**（渠道、产品线、地区），5 到 6 项，名字长 | 构成超过 6 项：横条页放不下，拆两页或者合并成「其他」 |
| 汇报对象会追问「这个数哪来的」 | 需要多个系列叠在一张图上比较 —— 这套版式一张图只有一个系列 |

## 内容槽位

| 槽位 | 从哪取 | 缺了怎么办 |
| --- | --- | --- |
| **数据文件** | 用户给的表格。按 `references/data.md` 读：先 `info` 看结构，**一次 `get` 读完所有要用的范围**，派生的数用 `eval` 在表上算，关键数用 `explain` 核出处 | **不编数据**。没有文件就停下来要；用户只口头给了几个数，就只做这几个数撑得起的页，把缺的页删掉 |
| **主数字**（封面、总览 hero 格） | 全年总量（营收、用户数、交付量） | 数据里最大、最想让人记住的那一个 |
| **总览四格** | 同比、利润率这类比率；一个计数（客户、门店）；一个季度走势（小柱子） | 少于四个就用 Bento 合并变体并格，不留空位（`visual-spec.md` Bento 两条硬规则） |
| **时间序列** | 四个季度；最后一个季度的三个月 | 只有季度没有月份：删第 4 页，3→5 直接坐标轴变横条 |
| **构成** | 5–6 项，带占比 | 占比让表格算（`eval` 或表里本来的公式），不要心算 |
| **对照** | 正好两项（去年 / 今年、计划 / 实际） | 没有就删第 6 页，5→7 用遮挡剪辑进结尾 |
| **一句解读** | 每页一句 | 只写数据本身能支持的话（「一月比一月高」「比上年增长三分之一」），不写原因推测 |

## 页面结构

```
1 封面      整页深蓝 .s-surface（data-id: page）+ 主数字 .t-metric.t-on-surface（data-id: rev），单位用 .t-h2 跟在下面
2 总览      Bento 基本格位：hero 格就是封面那块深蓝（data-id: page），主数字跟进来；
            四个小格：同比（stat）、利润率（highlight，.s-accent-soft）、计数（badge）、季度小柱子（chart，data-id: chart）
3 季度      数据页：右侧面板就是总览的 chart 格（data-id: chart）；左侧关键数字是总览里的同比（data-id: yoy）；
            四根柱子按比例，最后一根 .s-accent 写 data-split，坐标轴 .s-accent 写 data-id: axis
4 按月      数据页，同一块面板、同一条轴不动；最后一根柱子拆成三个月（.s-accent-soft ×2 + .s-accent）
5 构成      横向条形图页：最长的那条就是坐标轴（data-id: axis，.s-accent），其余 .s-surface
6 对照      对比页：左 .s-surface（data-id: page），右 .s-accent-soft
7 结尾      整页深蓝（data-id: page），一句话 + 数据来源两行 .t-label
```

**数字和单位分开写**：`<p class="t-display">34</p>` 后面跟一个 `<p class="t-h2">%</p>`。
Ledger 主题的数字是 Inter 600，「34%」三个字符实测 355px，小格子内容区只有 280px；拆开以后数字 2 位，单位小一档。
共享元素的两页要写**同一段数字**（都是「34」），单位各自跟着页面出。

坐标看样稿 `index.html`（做同款时 create_deck 会复制它）。转场锚三对：整页 / hero 格 / 对比页左面板（`page`），
总览 chart 格和数据页面板（`chart`），数据页坐标轴和横条页最长条（`axis`）。
其余按 `visual-spec.md` 各页面类型的标准位置摆。

引用顺序：`tokens.css → themes/ledger.css → palettes/ledger.css`。

## 动效原则

```
1→2  关系：封面的深蓝整页收成总览里「全年营收」那一格，主数字跟着落进格子   手法：形态变换  共享：page, rev
2→3  关系：「季度营收」那一格展开成数据页的图表面板，同比从小格飞成关键数字   手法：形态变换  共享：chart, yoy
3→4  关系：第四季度那根柱子拆成三个月                                        手法：一变多    分：q4
4→5  关系：图表的坐标轴变成构成排行里最长的那一条                            手法：形态变换  共享：axis
5→6  关系：换话题，从收入转到客户                                            手法：遮挡剪辑  方向：up
6→7  关系：对照页左边的深蓝面板撑满整页，成为结尾的底                        手法：形态变换  共享：page
```

- **每次翻页都是「打开总览里的某一格」**，所以共享元素和形态变换用得多。中间用一变多和遮挡剪辑隔开，
  没有连续三次同一类。
- **整页 ↔ 卡片两次**：1→2 收，6→7 放。两次都是同一个颜色类（`.s-surface`），首尾呼应。
  整页形状写在 section 的最前面，`border-radius:0`。
- **总览的格子按阅读顺序错开 0.08 入场**（0.8 起），格子里的字比格子晚 0.2；小柱子最后长出来。
- **2→3 的柱子不做共享元素**：面板和关键数字已经两对，再加四根柱子就六对，画面乱。
  柱子按「整页 ↔ 卡片接图表组合」等面板落定再长（1.1 起，每根加 0.1），数值和季度标签 1.7 出。
- **3→4 的面板、轴、单位标签前后完全一样**，一变多时原地不动，只有柱子在动；左边的文字原地淡出淡入。
- **4→5 坐标轴 720×4 → 880×56**：同是细长横条，长宽比 180 → 16，形态变换读得出「轴长成了第一条」。
  其余横条 `grow-right`，0.98 起每行加 0.08；占比数值 1.4 起最后出。
- **遮挡剪辑只用这一次**，就用在话题真的换了的地方。
- **赤橙每页只给一个数**：重点柱、最长条、或者 highlight 格，加上坐标轴。

## 硬规则

- 不编数据。页面上的每一个数都能在 `data/*.json` 里找到，`data/*.json` 的 `source` 指回表格的范围。
- 柱高、条长按数据比例算，取整到 1px；柱子底边压在坐标轴上。
- 百分比、占比、同比这类派生数由表格算（`calcgrid eval` 或表里的公式），不心算。
- 读表一次读完：一页要用的几个范围写进同一条 `calcgrid get`，不按单元格一个个读。
- 结尾页写出数据来源（文件 + 范围），转场计划注释里也写。

## 自检

除了 `references/transitions.md` 末尾的通用自检，再看：

1. 1→2：深蓝是**连续收缩**进 hero 格的，主数字没有闪；四个小格是在深蓝落定之后才出来的。
2. 2→3：图表面板是从总览右下那一格**长出来**的，不是在新位置淡入；柱子在面板落定之后才长。
3. 3→4：面板、轴、「单位：万元」一帧都不动；三根新柱子第一帧叠在原来第四季度柱子的位置。
4. 4→5：最长那条横条是从坐标轴连续变粗、变长的。
5. 6→7：深蓝从左边面板撑满整页，没有先消失再出现。
6. 每页的数和 `data/*.json` 对得上；结尾页的范围和转场计划注释里写的一致。

## 样稿

`index.html`：7 页，一家虚构的「北岸软件」的 2026 年经营数据。

`data/` 是整套读表流程的产物，照着 `references/data.md` 的「完整例子」一节跑出来的：

| 文件 | 内容 |
| --- | --- |
| `operations-2026.xlsx` | 虚构的经营数据表：汇总（带公式）、月度收入、渠道、客户四张表。用 `calcgrid create` 生成 |
| `summary.json` | 汇总!A2:B10：全年营收、同比、毛利率、四个季度 |
| `q4-months.json` | 月度收入!A11:B13：第四季度三个月 |
| `channels.json` | 渠道!A2:C6：各渠道收入和占比 |
| `customers.json` | 客户!A2:C3：付费客户、净收入留存 |

首页样片录 1–3 页（深蓝收成总览、总览一格展开成图表），封面取柱子长好那一帧。

```bash
node scripts/check-deck.mjs recipes/data-report/index.html
node scripts/capture.mjs recipes/data-report/index.html -o recipes/data-report/index.mp4
```
