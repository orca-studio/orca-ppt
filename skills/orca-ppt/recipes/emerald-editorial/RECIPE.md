# 分章节工作汇报

手法：序号块钻进章节

## 参考拆解

这是我们自己的样稿 `examples/emerald-editorial/`：一份给管理层的季度汇报，讲完开场和第一章，七页。
版面靠主题 `emerald-editorial` 撑起来，看点叠在三样东西上：

1. **只有两种面**：饱和翡翠绿的纸面，加一种深海军蓝的「蓝面」。文字压在绿上是海军蓝，压在蓝上反转成翡翠绿。
   圆角全是零，分隔全用 4px 结构线。
2. **深蓝块是一条线索**：从封面到数据页，画面上始终有一块深蓝形状，它一路变形 ——
   封面底部的横条 → 议程里的四个序号块 → 第 01 块被推近 → 章节页左半幅的面板 → 数据页的整页底色
   → 收拢裂成三张主题卡 → 三张卡收成一块「决定」面板。
3. **大数字只活在蓝面上**：关键数字 `18.6` 只在整页蓝底上出现，用 `.t-on-surface` 变成翡翠绿。

为什么成立：观众每次翻页都能说出「什么变成了什么」—— 横条分成了目录，目录的第一格就是这一章，
这一章的面板就是数据页，数据页的底色分成这一章的三个主题，三个主题收成要拍板的两件事。
六次翻页用了五种手法（一变多 → 整页推近 → 形态变换 → 一变多 → 多合一 → 遮挡剪辑），
没有连着两次同一种，但都落在同一块深蓝上，所以读起来是一条连续的路，而不是六个特效。
只有讲完第一章去结尾那一下真的没关系，就老实用遮挡剪辑断开。

## 适用 / 不适用

| 适用 | 不适用 |
| --- | --- |
| 有议程、分章节的汇报：季度复盘、年度规划、对管理层或投资人的路演开场 | 没有章节结构的单一主题稿 —— 没有议程，横条就没有东西可分 |
| 议程 3 到 5 条，每条一句短标题 | 超过 5 条。序号块一多，一变多的散开就成了一团；6 条以上拆两页议程或换版式 |
| 第一章开头就有一个关键数字（增长率、营收、用户数），再配一组 3–5 个随时间变化的数 | 第一章是纯文字论述，没有数字 —— 数据页撑不起来，整页蓝底上空着 |
| 第一章有 2–4 个要点，最后落到 1 个要拍板的结论或一组决定 | 要点超过 4 个 —— 整页蓝底裂成五六张窄卡，每张放不下一句话 |
| 想要高对比、杂志感、记得住的版面，字少 | 需要很多颜色区分系列、或者大段正文的内容 —— 这套只有绿、蓝、燕麦米三种面 |
| 只深入第一章，其他章节走通用流程 | 想让每一章都「钻进去」—— 整页推近一份稿子最多 2 次，不能每章用一次 |

## 内容槽位

| 槽位 | 从哪取 | 缺了怎么办 |
| --- | --- | --- |
| **标题**（两行） | 主题 | 拆成两个短语上下排，中间夹双横线（样稿是 "THE STATE" / "THE WORK AHEAD"）。中文每行不超过 6 个字 |
| **页眉页脚**（作者、日期） | 用户给的部门、日期 | 只放用户给了的；没给就留一边，不编机构名 |
| **议程条目**（3–5 条） | 用户的章节 | 每条一句短标题 + 一个大写小标签（Overview / Market…）。没给标签就只放标题 |
| **第一章的标题和一段说明** | 第一章内容 | 说明一两句，不超过三行。没有就只放标题，不编论述 |
| **章节页的两个小标签** | 第一章的要点数量（"Three themes" / "Two decisions"） | 没有就删掉这两个小块，不硬凑。写了就要和后面的主题页、决定页对得上 |
| **第一章的要点**（2–4 条） | 第一章内容 | 每条一个短标题 + 一句说明。没有要点就删掉主题页，数据页直接接决定页（这时 4→决定页用「整页 ↔ 卡片」形态变换收成面板） |
| **要拍板的事**（1–2 件） | 用户的结论、请求 | 每件一个短标题 + 一句说明。没有就删掉决定页，主题页直接遮挡剪辑到结尾 |
| **关键数字 + 一行单位说明** | 用户的数据里最想让人记住的那一个 | **不编数据**。没有就停下来要，或者用明显的占位（00.0）并在转场计划注释里写明 |
| **一组 3–5 个数**（柱状图） | 用户的数据；给的是表格文件就按 `references/data.md` 读，一次读整块，出处写进转场计划 | **不编数据**。柱子高度按真实比例；只有一个关键数字时删掉柱状图，不补假柱子 |
| **结尾的大字和一句话** | 用户的结束语 | 默认 "THANK YOU" / "谢谢"，副句写联系对象；没给就只放大字 |

## 页面结构

```
1 封面      两行大字夹一条双横线；底部一条整宽深蓝横条（data-split: chapters），上面一行副题
2 议程      标题 + 结构线；每行左侧一个深蓝序号块（data-split: chapters），第一块同时是钻入点（data-zoom: ch1）
3 章节页    左半幅深蓝面板（data-id: panel，data-zoom: panel）+ 巨大序号（data-id: num）；右半翡翠绿上是标题、说明、两个米色小标签
4 数据页    同一块面板撑满整页（data-id: panel，data-split: themes）；序号缩成左上角小标签（data-id: num）；关键数字 + 柱状图
5 主题页    翡翠绿底：眉题 + 标题 + 结构线；三张深蓝主题卡按三栏排（data-split: themes，data-merge: decide）
6 决定页    眉题、结构线和主题页同位置不动；一块整宽深蓝面板（data-merge: decide），里面左右两栏两个决定
7 结尾      燕麦米色块上扫，回到翡翠绿：大字 + 双横线，页眉页脚回到底部
```

坐标看样稿 `examples/emerald-editorial/index.html`（做同款时 create_deck 会复制它）。

- 第 5、6 页的眉题和结构线不写键，两页完全一样，原地不动。
- 议程序号块上的数字、章节面板上的文字、主题卡和决定面板上的文字都不写 `data-split` / `data-merge` / `data-id`，让它们自动入场。
- 章节面板贴左边出血，但面板里的文字照样守安全区：`left` 不小于 120。
- 主题卡 2 张或 4 张时：2 张用两栏 `left:120 / 1000 width:800`，4 张用 `left:120 / 540 / 960 / 1380 width:380`，高度不变。
- 议程是 4 条时序号块正好 4 个；3 条或 5 条时保持块尺寸 120、行距按版面重排，最后一块不要压到 `top:960` 以下。
- 数据页柱子数变了：一条 4px 的 `.s-accent` 当坐标轴，柱子宽 120、间隔 80，底边对齐坐标轴；
  前几根 `.s-accent-soft`、最后一根（最新的）`.s-accent`，季度标签在轴下方 40。

引用顺序：`tokens.css → themes/emerald-editorial.css → palettes/emerald.css`（`emerald` 是这个主题的默认配色，写出来是为了明确）。

## 动效原则

样稿的转场计划：

```
1→2  关系：封面底部的深蓝横条裂成议程的四个序号块               手法：一变多              键：chapters
2→3  关系：从议程第 01 行的深蓝序号块钻进去，进入第一章          手法：整页推近            from：ch1 → to：panel
3→4  关系：章节页左半幅的深蓝面板撑满整个画面，成为数据页底色    手法：形态变换（卡片 → 整页）共享：panel, num
4→5  关系：数据页的整页蓝底收拢、裂成第一章的三张主题卡           手法：一变多              键：themes
5→6  关系：三个主题收成一块面板，面板里是要拍板的两件事           手法：多合一              键：decide
6→7  关系：第一章讲完，换到结尾，没有视觉联系                     手法：遮挡剪辑（燕麦米色块上扫）
```

可复用的规则：

- **深蓝块全程同一个颜色类**（`.s-surface`）。配色 `emerald` 里蓝和燕麦米不是同色系，不能互变：
  一变多从蓝横条分出来的必须还是蓝块，形态变换前后的面板也都是蓝。要米色元素，就让它作为新元素入场，不要从蓝变过来。
- **一变多分出的块数 = 议程条数**，3 到 5 个（规范建议 2 到 6，再多散开就乱）。散开顺序按 HTML 顺序，议程从上往下写。
  序号和标题是文字，不写 `data-split`，块快落位时自动入场。一变多默认 1.2 秒，样稿录出来约 1.8 秒（含文字入场）。
- **钻入点要小**：整页推近按「钻入点占满画面约 75%」算倍数，限制 2 到 8 倍。120×120 的序号块正合适；
  别拿整行或半屏面板当钻入点，推不到 2 倍。时长 1.4 秒，不要改短。整份稿子最多用 2 次 —— 这个同款已经用掉 1 次。
- **章节面板同时是推近终点和形态变换起点**：第 3 页的面板写 `data-zoom="panel"`（接 2→3）又写 `data-id="panel"`（接 3→4），
  第 3、4 页都写 `data-auto-animate`。一页只能有一个 `data-st`，第 3 页的是 `zoom-through`。
- **形态变换只配对 2 个**（面板 + 序号），在「一次 1 到 4 个」的范围里。面板从半屏撑到全屏、位移大，
  写 `data-auto-animate-duration="1.2"`。序号 `t-display` → `t-label` 只换 class，标签都是 `<p>`、文字都是 "01"。
- **数据页的新元素按 1.2 秒那一行排**：标题 0.8，说明、关键数字、单位、坐标轴 1.0；
  柱子按「整页 ↔ 卡片接图表」整体后移，从 1.1 开始每根 +0.1（1.1 / 1.2 / 1.3 / 1.4，`data-enter="grow-up"`），
  坐标轴 `grow-right`，季度标签最后 1.7。图表场景允许超过「最后一个 ≤ 时长 + 0.3」的上限。
- **整页蓝底再裂一次**：数据页的整页面板同时写 `data-id="panel"`（接 3→4）和 `data-split="themes"`（接 4→5），互不影响。
  一变多第一帧三张卡叠成整页，散开时翡翠绿才露出来 —— 观众看到的是「数据页的底色分成了三个主题」，不是换了一页。
  分出的卡还是 `.s-surface`（不变色）。卡上的文字按卡落位的顺序成组入场：卡在 0.9 / 0.98 / 1.06 秒落位，
  文字写 `data-enter-delay` 0.8 / 0.88 / 0.96；眉题、标题、结构线 0.6。
- **一变多之后接多合一**：同一组三张卡，5→6 写 `data-merge="decide"` 收成一块整宽面板（还是蓝），
  讲的是「三个主题归结成两件要拍板的事」。合拢约 1.06 秒完成，面板里的文字 `data-enter-delay` 从 1.0 开始、每组 +0.08，
  中间那条 `.s-accent` 竖线 `grow-up` 1.0；面板外的标题 0.7。眉题和结构线两页一模一样，原地不动，
  观众的视线就只落在合拢的那一下。
- **一变多两次不挨着**：1→2 和 4→5 都是一变多，中间隔着两种别的手法；同一种手法别连着两次用在蓝块上，读起来会像重播。
- **结尾用遮挡剪辑断开**：第一章和结尾之间没有视觉联系，硬接共享元素反而假。色块用默认强调色（燕麦米），方向 `up`。
  这是全稿唯一一次遮挡剪辑。
- **六次翻页五种手法**，不连续两次同一种。停留：封面、结尾 2.5 秒，其余各页 3 秒（信息多）。

## 硬规则

- 深蓝块（横条、序号块、章节面板、整页底色）全是 `.s-surface`，不在蓝和燕麦米之间变色。
- 大数字只放在整页蓝底上，加 `.t-on-surface`；`.t-metric` 不要直接压在翡翠绿上（对比不足）。
- 整页底色写 `border-radius:0`，是 section 第一个子元素；章节面板也是第一个子元素。
- 不写颜色值、不引别的配色，圆角保持全零，少用 `.s-dot`（圆点会破掉「全是直角」）。
- 整页推近只用 1 次，遮挡剪辑只用 1 次。
- 不编数据、不编议程条目。

## 自检

除了 `references/transitions.md` 末尾的通用自检，再看：

1. 1→2：第一帧四个序号块叠在封面横条的位置、看起来还是一条；然后依次散开到四行，不是在新位置淡入。
2. 2→3：镜头是以第 01 块为中心推进去的，切点后从左半幅面板拉出，没有露出画布边缘。
3. 3→4：面板是从左半幅连续撑满整页的，"01" 从面板中央飞到左上角缩小；数据页标题在面板基本铺满之后才出。
4. 柱子在坐标轴画出来之后才一根根长出，底边全部压在坐标轴上，高度和数据成比例。
5. 4→5：第一帧整页还是蓝的，三张卡是从整页收拢分开的，不是在三栏位置淡入；数据页的文字和柱子在卡收拢前就退掉，不压在卡上。
6. 5→6：三张卡依次飞向同一块面板、叠成一块，眉题和结构线一动不动；面板里的字在合拢之后才出。
7. 6→7：燕麦米色块从下往上扫过一次，结尾回到翡翠绿，页眉页脚位置和封面呼应。
8. 整份稿子里画面上从没出现过第二种「蓝」，也没有蓝块中途变成米色的浑浊帧。

数据（18.6% 同比增长、四个季度的柱子）、主题和决定都是占位。首页样片只录第 2–5 页（钻进章节、面板撑满成数据页、整页蓝底裂成三张主题卡），
