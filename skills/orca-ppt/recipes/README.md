# 同款

用户拿来一个参考（一段视频、一份别人的稿子、一句「像 XX 那样」），说「做个同款」时，读这里。

一个同款是**一份样稿 + 一份配方**。样稿是能跑的答案，复刻就从它起头；配方只写样稿表达不了的：
参考是怎么做到的、什么内容不适用、用户要给什么、页数变了怎么增删、为什么这么接。
写一长串文字给你，不如丢一个例子给你 —— 所以坐标、写法看样稿，不在配方里再描述一遍。

不选同款、只给主题和内容框架的需求，不读这里，按 SKILL.md 的流程走通用规范。

## 怎么用一个同款

1. 读它的 `RECIPE.md`。先看「适用 / 不适用」，用户的内容撞上「不适用」就别硬套，告诉用户为什么，换通用流程。
2. 按「内容槽位」从用户给的材料里取值。缺的分两种：文案、结构、示意性的例子自己补，把假设写进转场计划的注释里，
   不要一上来问一串问题；**数字一律不编**，没有就停下来要，或者放明显的占位（`references/data.md`）。
3. **以样稿为起点**：应用里用 `create_deck` 的 `from: "recipe:<id>"` 复制一份样稿（主题、配色、素材都带上）；
   没有应用就复制样稿目录，把 `../../` 改成到 skill 根目录的相对路径。在这份上换成用户的内容，
   节点数、页数不同时按「页面结构」增删页、改转场锚。不要从空白文件照着配方文字重写。
   在应用里改字用 `edit_text`（能撤销，不会碰坏转场属性），转场计划注释里的字用 `edit_plan`，删页用 `edit_pages`。
   样稿里的示例年份、公司名、标语、句子一条也别留：换成用户的，或者删掉。
4. 按 SKILL.md 流程第 6–8 步核版式、录制、看视频，再对一遍配方自己的「自检」。

## 写一个新同款

一个目录一个同款：`recipes/<id>/`，里面这几样东西：

| 文件 | 内容 |
| --- | --- |
| `RECIPE.md` | 配方。开头 frontmatter 给机器读（应用的同款列表靠它），正文给 agent 读 |
| `poster.jpg` | 首页卡片和官网的封面，**必须有**。写好样稿和 frontmatter 后跑 `node scripts/render-poster.mjs recipes/<id>`：按 `preview` / `cover` 截一张 1280×720，并在 frontmatter 补上 `poster: poster.jpg`。封面跟着同款进仓库，应用和官网都不现录样片；样稿改了画面就重跑一次（加 `--force`） |
| `index.html` | 能跑的样稿，用占位内容把整个配方演一遍，**至少 6 页**（首页点进去要能看完一份完整的稿子，不只是演完手法）。`examples/` 里已经有合适的稿子时不放这个，用 frontmatter 的 `sample` 指过去 |
| `cover.html` + `cover.jpg` | 可选，代替 `poster.jpg`。样稿里没有哪一帧能一眼说清这个同款时（主角和结果分在几页里），用样稿的主题、配色和元素拼一页封面：页面里铺一个 1920×1080 的 `.cover-canvas`，`node scripts/render-cover.mjs recipes/<id>/cover.html` 截成 `cover.jpg`，frontmatter 写 `poster: cover.jpg`。封面要能看出标题说的场景，主角、结果都在画面里 |

`RECIPE.md` 的 frontmatter：

```yaml
---
id: recap-credits          # 和目录名一致
title: 电影级片尾         # 给人看的名字：写效果（观众看到什么），场景写进 summary
mode: 汇报稿               # 汇报稿 / 故事稿
order: 13                  # 上架序号，大的排在首页前面。新同款写现有最大值 + 1，就排第一张
sample: ../../examples/x   # 样稿用 examples/ 里现成的那份（相对本目录，不能出 skill 目录）。可省略（用本目录的 index.html）
summary: 适合的场景：效果一句话  # 冒号前写场合（「项目收尾致谢、结尾页」），后面写看到什么；不是标签
preview: 4-5               # 看点在哪几页（页号从 1 数，含两头）：render-poster 从这里截封面。可省略（整份）
cover: 4.9                 # 封面取看点开头算的第几秒，可省略（默认 75% 处）
poster: poster.jpg         # 封面图（相对本目录），首页卡片和官网都用它。render-poster 会写上
---
```

正文按这几节写，顺序不变 —— agent 是按这个顺序干活的：

1. **参考拆解**：参考作品是怎么做到的，哪几样东西叠出来的。只写观察，不写评价。
2. **适用 / 不适用**：什么内容能套，什么内容套了会露馅。
3. **内容槽位**：用户要给什么、缺了怎么补。每个槽位写清默认值。
4. **页面结构**：几页、每页的主角；节点数、页数变了怎么增删，转场锚的坐标怎么跟着算。样稿里看得到的坐标不用逐个抄一遍。
5. **动效原则**：转场计划怎么写、时长和节奏的规则、**为什么**。
6. **硬规则**：撞上就错的东西。
7. **自检**：录完看什么。

**样稿必须 0 错误。** 例子是 agent 学写法的主载体，样稿里一条违规，照着做的稿子就都违规。
`pnpm test` 会对所有示例和样稿跑 `check-deck`，有 `✗` 就不过。

**同款不许自带动画实现。** 参考里的效果引擎做不到时，先把能力加进 `runtime/`
（同时写进 `transitions.md` 或 `visual-spec.md` 的通用规范），配方里只引用它。
否则每个同款各带一份私有 JS，下一个同款想复用就得抄。

## 案例也放首页

有的参考没有一个能单独拿走的手法，好看在一整套风格从头贯穿到尾（国风人物介绍：插画、宣纸配色、毛笔字、水墨转场，
拆开看每样都平常）。这种不写成同款，写成 `examples/<id>/` 下一份完整的稿子，加一个 `EXAMPLE.md` 让它上首页。

和同款的区别：

- 首页卡片**没有「做同款」**，点开在工作台里看整份稿子。卡片标题后面标「案例」。封面一样要有，同样用 `render-poster.mjs` 截。
- `create_deck` 不能 `from: recipe:<案例 id>`：案例是给 agent 学风格怎么贯穿一整份稿子的，不是起头的样稿。
- 已经被某个同款的 `sample` 指着的示例不用写 `EXAMPLE.md`，首页已经有它那张同款卡。

`EXAMPLE.md` 开头的 frontmatter 给应用读，键的意思和同款一样；正文可选，写给 agent：看这份稿子学什么（见 `examples/ink-portrait/EXAMPLE.md`）。

```yaml
---
id: ink-portrait           # 和目录名一致，也不能和哪个同款撞
title: 人物生平介绍       # 写场景
mode: 汇报稿
order: 24                  # 和同款共用上架序号
summary: 一句话，什么场合用
preview: 1-1               # 封面从哪一页取。可省略（第一页）
cover: 2.5                 # 封面取那一页的第几秒，可省略（默认 75% 处）
poster: poster.jpg         # 封面图，render-poster 会写上
---
```

标准和同款样稿一样：至少 6 页、0 错误。标题写场景：案例好看在一整套风格，没有一个单独的效果可以起名。
`examples/` 在 `skills/orca-ppt/.gitignore` 里是白名单，新案例要加一行 `!examples/<id>/`，不然整个目录不进仓库。
