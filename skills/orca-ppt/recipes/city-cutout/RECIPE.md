# 城市漫游

手法：文字镂空封面

## 参考拆解

参考是一条 PPT 技巧笔记（WPS / PowerPoint 手动操作）：

1. **背景**：一张城市天际线照片，图片填充铺满整页。
2. **色块和字**：插一个矩形盖住画面上半截，再插一个文本框写大字 SHANGHAI，压在矩形上。
3. **剪除**：先选矩形、再选文本框，「合并形状 → 剪除」—— 字从矩形里挖掉，照片从字里透出来。
4. **渐变**：剪出来的形状改成线性渐变，自上而下三个色标，颜色都是 `#879BAE`，透明度 0% / 15% / 100%（位置 0% / 55% / 100%），无线条。
   色块上半截是实的，往下越来越透，最后融进照片。

参考只有一页封面。本同款把它做成一份城市漫步：封面收成左上角的角标，镜头在同一张照片里推近、横移，一站讲一个地方，最后拉回封面。

看点只有一个：

> **字是窗。** 字孔里永远是它正后方的那块照片，色块缩成角标、镜头怎么挪，窗里的景跟着换。

## 适用 / 不适用

| 适用 | 不适用 |
| --- | --- |
| 城市、景区、园区、项目介绍，有一张好的全景照片 | 没有照片，或照片是一张产品白底图：字孔里透出来的是一片白 |
| 标题是一个短词：地名、品牌名，8 个字母 / 5 个汉字以内 | 标题是一句话：字号压不下来，字孔细得透不出东西 |
| 照片上半截是天空、水面这类干净的大色块 | 照片满幅都是楼群、人群：字一透就糊，看不出字形 |
| 正文是几个「地点 + 一两句话」 | 每页要放图表、长段落：照片当底撑不住，换通用流程 |

## 内容槽位

| 槽位 | 从哪取 | 缺了怎么办 |
| --- | --- | --- |
| **标题**（镂空的那个词） | 地名、品牌名 | 用稿子的主题词；超过 8 个字母时先问能不能换短的说法 |
| **一张全景照片** | 用户给的 | 没有就停下来要。示意稿可以用 AI 生成，但要在转场计划注释里写明 |
| **几个站点**（名字、一句标题、一两句介绍） | 用户的行程、介绍材料 | 文案可以自己补；**数字不编**（`references/data.md`） |
| **每个站点在照片里的位置** | 看照片 | 自己找；站点不在照片里的，那一站不推镜头，只换卡片里的字 |
| **封面和结尾的一句话** | brief | 自己补，结尾呼应封面 |

## 页面结构

样稿 6 页：

| 页 | 镜头 | 色块 |
| --- | --- | --- |
| 1 封面 | 全景 | 盖住上半截，1920×720 |
| 2–5 每站一页 | 推近、横移到这一站 | 收成左上角的角标，720×270，不动；右下一张毛玻璃卡片讲这一站 |
| 6 结尾 | 拉回全景 | 放回封面的大小 |

**站点数不同时**：一站一页，增删中间页就行，角标和卡片的位置不变。

**镜头怎么摆**（坐标看样稿）：
- 照片的 `left / top / width / height` 就是镜头。推近 = 宽高按同一倍数放大；横移 = 只改 `left / top`。
  放大后要盖满画布：`left ≤ 0`、`top ≤ 0`、`left + width ≥ 1920`、`top + height ≥ 1080`。
- 站点在照片里的点 `(px, py)`（按照片原图像素量）要落在画面的 `(cx, cy)`：
  `left = cx − px × 倍数`，`top = cy − py × 倍数`，倍数 = 照片显示宽 ÷ 原图宽，然后按上一条夹住。
- **卡片后面要暗一点。**卡片是毛玻璃（`.s-glass`，`visual-spec.md`「毛玻璃卡片」），白字压在透出来的照片上：卡片落在夕阳、亮天上时 `check-deck` 会报对比度，挪镜头让卡片落在楼群、江面上。
- **角标后面要留天空。**镜头往下摇到楼群时，角标的字孔里全是楼，字就糊了 —— 样稿第 3 页因此没有摇到底。

## 动效原则

样稿的转场计划（写在样稿开头的注释里）：

```
1→2  共享元素（形态变换）  封面收成角标，镜头推向第一站
2→3  共享元素              镜头横移，角标和卡片不动，卡片里的字换掉
3→4  共享元素              镜头沿江摇
4→5  共享元素              镜头推近
5→6  共享元素（形态变换）  镜头拉回全景，角标放回封面
```

- **两个共享元素：照片 `city`（镜头）和色块 `veil`（字窗）。** 1→2 两个一起动：色块往角上收、镜头往里推，
  观众看到的是「标题退到角上，画面走进城里」。中间几页色块不动，只有镜头在动 —— 视线跟着照片走。
- **色块只缩放，宽高比全片不变**（1920:720 = 720:270）。字是画在色块里的，宽高比一变字就对不上。
- **卡片等镜头停了再进**：第 2 页卡片 `data-auto-animate-delay="1.0"`，比镜头的 1.4 秒早一点点落定。
  之后几页卡片本身不动（同一个 `data-id="card"`），只换里面的字，字的延迟 0.8–0.9 秒。
- 镜头一次只做一件事：推近、横移、摇，别又推又摇。推近不超过 1.4 倍（样稿 3136 → 4300），再大照片会糊。
- 转场时长 1.2–1.4 秒；停留封面 2.5 秒、站点页 3 秒。

## 硬规则

- 色块的写法、`mask` 的 id 每页不同、字号类 `.t-knockout`，见 `visual-spec.md`「文字镂空」。不要自己写渐变、不要写色值。
- 色块上的字（封面的标签和副标题）加 `.t-on-surface`，写在色块**后面**。
- 站点卡片用 `.s-glass`，卡片上的字加 `.t-on-glass`。不用实心的 `.s-surface`：一块配色里的深色压在照片上，像贴上去的。
- 照片整份稿子一张、一个 `data-id`，所有页都在。
- 色块整份稿子一个 `data-id`，所有页都在，宽高比不变。

## 自检

除了 `transitions.md` 末尾的通用自检，再看：

1. 每一页停下来时，镂空的字形都认得出来：字孔里是天空或水面，不是一团楼。
2. 1→2 和 5→6 的整个过程里，字孔一直透着照片，没有哪一帧变成实心的色块或者整块消失。
3. 色块的下沿是淡出去的，看不到一条硬边。
4. 镜头推拉、横移时没有露出画布底色。
5. 毛玻璃卡片后面透出来的是照片的颜色，卡片上的白字每页都读得动（`check-deck` 量过对比度，再用眼睛看一遍）。

## 导出 PPTX

色块整块截成一张透明底的 PNG（字孔和淡出都保留），照片是原生图片；两张图按名字配对，走「平滑」。
毛玻璃卡片退成一块半透明的暗色卡片（模糊导不出来），字还是文本框。
在 PowerPoint 里不能改那个词，要换字回网页改了再导。

## 样稿

三份样稿，同一个配方，换照片、换配色、换一个专属镜头 —— 看的时候比一比哪些变了、哪些没变：

| 样稿 | 照片 | 配色 | 专属镜头 |
| --- | --- | --- | --- |
| `index.html` 上海 | 一张晚霞全景 `art/city.jpg` | ledger，深海军蓝色块 | 推近、横移、沿江摇 |
| `hangzhou.html` 杭州 | 湖景 `art/hangzhou.jpg` + 茶山 `art/tea.jpg` + 雾 `art/fog.webp` | washi，色块写 `--knockout: var(--surface-2)` 用苔绿灰 | **雾散开**：湖景上压两层雾（同一张透明底的雾图，`fog-a` / `fog-b`），封面雾浓，翻到第一站两层雾往左右走出画面、变淡；结尾雾再合拢 |
| `chongqing.html` 重庆 | 一张竖长夜景 `art/chongqing.jpg`（1920×2880） | neon-night，霓虹粉色块（夜景暗，色块要亮，字孔才读得出来） | **往下沉**：镜头每页只往下移（偶尔推近），从山顶的楼沉到江面；CHONGQING 9 个字母，`viewBox` 放大到 2240×840 |

都是 6 页（封面 → 四站 → 结尾），照片都是 AI 生成的，站点文案是示意。

**换城市时先看照片能不能撑起四站**：一张照片里找得到四个各不相同的地方，就一张照片推拉横移；
找不到就加第二张（杭州的茶山），换照片那一次是交叉淡化，角标和卡片不动。
**换照片要两页都写两张**，要隐去的那张写 `opacity:0`，两张都是共享元素 —— 整个转场时长里交叉淡化，镜头还能同时推拉。只在一页写的话，旧照片按「没配对的元素」0.35 秒就淡没了，看着是硬切（杭州第一版 3→4 就是这样）。
**专属镜头只用共享元素做**：雾是一层图片，往两边走、变淡；往下沉是照片的 `top` 一页比一页小 —— 都不需要新的引擎能力。
