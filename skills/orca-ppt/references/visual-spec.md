# 视觉规范（汇报稿）

转场能对上的前提，是前后两页的元素落在同一套网格、字号、颜色上。
所以这份规范约束得比一般幻灯片模板更死：**只许用这里列出来的值。**
故事稿（整页照片）的规范见 `story-mode.md`。

## 画布和网格

- 画布 1920×1080。每页的直接子元素都绝对定位：`style="left:…px; top:…px;"`。
- **面板、卡片这类形状，坐标和尺寸取 40 的倍数。**
- 可以不是 40 倍数的情况：
  - 文字的 `top`，用来在卡片里垂直对齐。
  - 居中文字的 `left`，按公式算出来是多少就写多少。
  - 图表里柱子、条的长度，按数据比例算，取整到 1px。
- 安全区：左右 120，上下 80。内容不许超出 `left 120 ~ 1800`、`top 80 ~ 1000`。
- 内容区宽 1680。常用分栏：
  - 两栏：`left:120 width:800` + `left:1000 width:800`（栏距 80）
  - 三栏：`left:120 / 680 / 1240`，每栏 `width:520`（栏距 40）

## 文字

只用下面这些字号类，不许在 style 里写 `font-size`、写死的颜色：

| 类 | 字号 | 用在哪 | 一行最多 |
| --- | --- | --- | --- |
| `.t-display` | 160 | 封面标题，章节标题，结尾；数字卡片里的数字。见下 | 8 个字 |
| `.t-metric` | 280 | 关键数字，自带强调色。一页最多一个 | 见下 |
| `.t-h1` | 72 | 内容页标题 | 20 个字 |
| `.t-h2` | 48 | 条目，卡片标题 | 按 width 换行 |
| `.t-body` | 36 | 说明文字，暗色 | 按 width 换行 |
| `.t-label` | 24 | 页眉、单位、坐标轴刻度、卡片小标签、数据出处 | 一行 |
| `.t-credits` | — | 只用在回顾片尾的名单列表（见「结尾页 · 回顾片尾」） | — |
| `.t-knockout` | 320 | 只用在文字镂空的 `<mask>` 里（见「文字镂空」） | 8 个字母 / 5 个汉字 |

修饰类：`.t-accent`（强调色），`.t-dim`（暗色）。

`.t-accent` 和 `.t-metric` 用的是 `--accent-text`（强调色的**文字档**），不是 `.s-accent`
色块那个 `--accent` —— 两者是同一个强调色的深浅两档，合成一个值的话，落在浅色页面底上的
强调文字会消失（blush 的奶油黄压在腮红粉上只有 1.02:1）。落到面板或强调块上时另说，
见下面 `.t-on-surface` / `.t-on-accent`。

**`.t-display` 的数量**：
- 当标题用（封面、章节、结尾）时，一页只有一个。
- 当数字卡片里的数字用时（几张卡片各放一个大数字），每张卡片一个，一页最多 3 个。
  这样的页面不再用 `.t-display` 做标题，也不和 `.t-metric` 放进同一张卡片。
  **Bento 网格页例外**：hero 格和 stat / badge / highlight 格各放一个，一页可以到 4–5 个，见「Bento 网格页」。

**估算宽度**：
- 中文字：宽 ≈ 字号。
- 数字、英文、小数点：宽 ≈ 0.55 × 字号。`.t-metric` 的「18.6」≈ 4 × 154 = 616px。
- 「万」「%」这类放在数字后面的，按中文字算。

**需要换行的 `.t-h2` `.t-body` 必须写 `width`。**

**居中**：可以在 style 里写 `text-align:center`，同时写 `width`，`left` 按「中心 − width/2」算。

**文字标签**：一律用 `<p>`。做共享元素时前后两页的标签必须一致（`transitions.md`「共享元素」第 2 条），统一用 `<p>` 最省事。

## 颜色和形状

颜色只用这些类。行内 style 不许写色值（`#…`、`rgb(…)`、颜色名）—— 换配色时它不会跟着变。
稿子也不许引自己的样式表。唯一的例外是同款 `style-swap` 里浏览器框内的示意网页，规则见 `style-swap.md`。
确实要在行内用颜色时（比如绕圆心转的圆环用 `radial-gradient` 挖洞），只写变量：`var(--surface)`、`var(--accent)`。
`opacity` 可以写。下表写的是默认主题的样子，换主题后颜色跟着变，用途不变（见 `themes.md`）：

| 类 | 样子 | 用在哪 |
| --- | --- | --- |
| `.s-surface` | 深灰面板，大圆角 | 内容卡片，大面板 |
| `.s-surface-2` | 浅一级的灰，中圆角 | 面板里面的小卡片，图表的普通柱 |
| `.s-accent` | 橙色，小圆角 | 强调条，图表的重点柱，分割线 |
| `.s-accent-soft` | 暗橙，中圆角 | 高亮卡片，高亮行的底 |
| `.s-dot` | 橙色正圆 | 圆点，图标底，徽章 |
| `.s-spot` | 压暗整屏的幕布，中间一个圆洞 | 信息多的页面上聚焦一处重点 |
| `.s-knockout` | 一块色块，字从里面挖空，往下淡出 | 照片封面：照片从标题的字里透出来（见「文字镂空」） |
| `.s-glass` | 半透明暗玻璃，后面的照片模糊着透出来 | 压在整页照片上的文字卡（见「毛玻璃卡片」） |
| `.s-lamp` | 一盏吊灯（透明底的灯图），铺满画布，引擎按 `data-lamp` 挂灯、画光束和光圈 | 深底的竞选、介绍、产品稿：灯照到哪讲到哪（见 `transitions.md`「吊灯」） |
| `.s-lit` | 被灯照亮的那一层，铺满画布：光圈里看得见，光圈外只剩余光 | 和 `.s-lamp` 一起用，放要被光显出来的照片 |

线条类（只用在 `<svg>` 里的 `path` / `polyline` / `line` 上）：`.l-accent` `.l-surface` `.l-text` 线宽 6，`.l-dim` 线宽 2（基线、参考线）。
不许在 svg 上写 `stroke` 颜色，虚线可以写 `stroke-dasharray`。

文字颜色类 `.t-on-surface`：放在 `.s-surface` 形状上面的文字用它。默认主题下和普通文字同色，浅色主题下会变成浅色。
**`.t-metric` 放在面板上时必须再加它** —— `.t-metric` 自己是 `--accent-text`，那是给页面底
准备的深色，压在深面板上就成了深字压深底。

文字颜色类 `.t-on-glass`：放在 `.s-glass` 上面的文字用它，固定白色，不跟配色走（理由见「毛玻璃卡片」）。

文字颜色类 `.t-on-accent`：放在 `.s-accent` / `.s-accent-soft` 上面的文字用它。
**强调块上的文字一律加它**，不要靠继承 `--text` —— 全局只有一个文字色的话，
总有一套配色的字会在强调色上消失（clearing 的白字压在浅黄上只有 1.24:1，
`npm run palettes` 抓到过这个）。

- 形状元素写 `left top width height`。`.s-dot` 的宽高必须相等。
- `.s-spot` 的 `left top width height` 是**洞**的位置和大小，不是幕布的。一页最多一个洞，
  放在 section 的最后（压在内容之上）。
  **洞是正圆**（宽高相等），直径取「要突出的那张卡片长边再大一点」，让卡片整个落在洞里。
  圆才有打光的感觉；圆角矩形看着像把卡片抠下来。旁边的卡片被圆边切到一点没关系，那就是聚光的样子。
  洞沿自带一圈强调色描边（`.s-spot` 里已经写好），别自己去掉 —— 洞压在纯黑底上时，全靠它才看得出是个圆。
  洞在页与页之间怎么走，见 `transitions.md`「镂空聚焦」。
- 要一个暗橙色的圆，写 `class="s-accent-soft" style="…; border-radius:50%;"`。
  卡片、面板的圆角由主题给，不要自己写；要改只写 `50%`（正圆）、`0`（铺满画布的整页形状，见 `transitions.md`「整页 ↔ 卡片」）
  或主题的圆角变量 `var(--radius-s|m|l)`。拼图形时（灯头的半圆、灯身的圆角）属于图形本身的几何，可以写像素。
- **强调色（`.s-accent` `.s-dot` `.t-metric` `.t-accent`）的面积加起来，不超过画面的 15%。**
  满屏强调色只出现在遮挡剪辑的色块里；带领头元素的遮挡剪辑，接住色块的那块整页面板也算（`transitions.md`「遮挡剪辑」）。

### 文字镂空（`.s-knockout`）

整页照片上盖一块色块，标题从色块里挖空，照片从字里透出来；色块自上而下淡出，和照片接上。
PowerPoint 里的做法是「矩形 + 文本框 → 合并形状 · 剪除 → 渐变填充」。完整写法照抄同款 `city-cutout` 的样稿：

```html
<div data-id="veil" class="s-knockout" style="left:0px; top:0px; width:1920px; height:720px;">
  <svg viewBox="0 0 1920 720">
    <mask id="ko-1"><rect width="1920" height="720"/><text class="t-knockout" x="960" y="460">SHANGHAI</text></mask>
    <rect width="1920" height="720" mask="url(#ko-1)"/>
  </svg>
</div>
```

1. `viewBox` 和色块的宽高一致（单位就是像素）；字的 `x` 写色块宽的一半（`.t-knockout` 自带居中），`y` 是基线。
2. **每页的 `mask` 用自己的 `id`**（`ko-1`、`ko-2`……），`rect` 的 `mask` 指向本页那个。id 重了，`url(#…)` 只认文档里的第一个，这一页的色块会去用别的页的字（那一页没显示时字孔整个消失）。
3. 色块颜色默认 `--surface`，色块上的字加 `.t-on-surface`。照片主色更配二级面时写 `style="--knockout: var(--surface-2)"`
   （莫兰迪配色的 `--surface-2` 就是参考里那种雾蓝灰）。淡出位置写 `--knockout-fade`（默认 `55%`），不要自己写渐变。
4. **字孔要落在干净的地方。** 字里透出来的是它正后方那块照片：天空、水面、大片墙面看得清字形，楼群、人群这种碎画面一透就糊。
   摆照片时让字孔后面是天空 —— 镜头推拉、横移之后也一样（同款样稿第 3 页为此把镜头往上留了天）。
   **色块和字孔里的画面要一深一浅**：白天的照片字孔里是亮的天，色块用深色；夜景字孔里是暗的，色块要用亮色
   （重庆样稿用霓虹粉，第一版的深梅紫和夜景一样暗，字形整个糊进灯光里）。
5. 要做共享元素（封面收成角标、角标放回封面），**只缩放不改宽高比**：宽高比一变，字就和色块对不上。
6. 一行最多 8 个字母或 5 个汉字。字形要粗：细笔画的字孔太窄，透不出东西。
   多一两个字母时（CHONGQING 9 个），**把 `viewBox` 按同样比例放大**（1920×720 → 2240×840），字号类不变，字在画面上就小一号；`x`、`y` 跟着按比例换算。
7. 角标压在碎画面上（楼群、人群）字认不出来时，在那几页的色块上写 `--knockout-fade: 90%`，字所在的那一截色块更实；封面保持默认。


### 毛玻璃卡片（`.s-glass`）

文字卡压在整页照片上时用它，不用 `.s-surface`。实心面板是配色里的颜色，和照片没关系，像贴上去的；
玻璃后面透着模糊的照片，换哪张照片都搭，镜头推拉横移时卡片的底色跟着画面变。

1. 卡片上的字一律加 `.t-on-glass`（白字）。玻璃的底是照片，配色里没有哪个文字色能保证压在任意照片上都读得动，所以它不跟配色走。
2. **照片太亮的地方放不住白字。** `check-deck` 会把字藏起来截图，量字底下那块照片的亮度：不到 4.5:1 报错。
   报了就挪卡片到画面暗一点的地方，或者挪镜头，不要自己加深玻璃。
3. 底下是纯色的页面用 `.s-surface`：玻璃没东西可透，只剩一块灰。
4. 导出 PPTX 时模糊截不出来，退成一块半透明的暗色卡片，字还是文本框。


## 页面类型

每页只放一个主角。照这些坐标摆，前后页才对得上。
唯一的例外是「Bento 网格页」，它一页并列五块，规则见那一节。

**认得准类型的 `<section>` 标上它的类型**：`<section data-page="data">`。
id 只能用 `runtime/pages.json` 里的，词表外的写法 `check-deck` 会报错。

标它不是为了给人一个菜单挑 —— 本产品的人不摆页面，他说话。标它是因为：
说不出一页是什么类型，就没人能校验它、指代它（「把第 3 页改成对比页」）、
或者据此规划转场。转场靠的是「同一个角色在前后页都认得出来」，而角色的位置由页面
类型定 —— 自由发挥的坐标正是转场杀手，而且坏了不报错，要放映到那一下才发现。

**认不准就别标。** 标错一页会同时误导校验、agent 和转场规划，比留空糟得多；
没标的页只做通用检查（安全区、强调色面积这些）。

**页面类型跨主题通用。** 这是本规范和 Keynote 那类产品最实质的区别：Keynote 的每个
主题要把每个布局重画一遍，而这里的页面类型只写**坐标和语义类**（`.t-display`、
`.s-surface`），颜色字体全从主题变量来 —— 同一份版式在五个主题下都成立，写一次就够。

守住这一点的代价是一条硬约束：**页面类型只能用 `tokens.css` 里有的类。**
用了某个主题自己新增的类（`.s-ring` 这种），这份版式在没定义它的主题下就漏样式，
而且要到换主题时才发现。`.t-label` 因此被提进了 `tokens.css` —— 它本来只在四个主题
里有，`templates/layouts/bento.html` 用了它，在 clearing 下就是漏的。

### 先看内容，再选页面类型

**最容易踩的雷是反过来：先挑了一个好看的版式，再把内容硬塞进去。**
版式承载内容的「形状」是固定的——塞不进去就会变形，读者看出来的关系是假的。

要守的是**形状**：没有大小关系的东西不要进图表，不是对等的两项不要并排，
凑不满的格子不要硬撑。

| 内容 | 用 | 严禁用 |
| --- | --- | --- |
| 起手 | 封面 | 一份稿子只有一个 |
| 换话题，只有编号和章节名 | 章节页 | 别在章节页上挂数据或条目，那是下一页的事 |
| 3–6 条并列的**定性**条目 | 列表页 | 要比较量级的数据 —— 条目是文字行，读者比不出大小 |
| 4–6 项排名对比，名字长 | 横向条形图页 | 少于 4 项。四条以下撑不起一整页，用数据页的柱状图 |
| 4 步的流程或时间演化 | 横向时间线页 | 无序的并列 —— 轴会让观众读出不存在的先后。超过 4 步拆两页 |
| 一个关键数字 + 一组图表 | 数据页 | 本身**没有可比量级**的并列概念。「智能补全 / 实时协作 / 自主代理」做成柱子，读出来的高低是假的 |
| 正好两项对照（旧 / 新、A / B） | 对比页 | 三项以上。挤进两栏读不出对等关系 |
| 一个主角 + 4 条佐证 | Bento 基本格位 | 五块等权时 —— 没有主角就不该占着 hero 格 |
| 一个主角 + 8 条 | Bento 密集版 | 不足 6 块。格子撑大或空着，网格就散了 |
| 9 条等权，没有主次 | Bento 三栏版 | 有明显主次时，主角会被淹没。其中一格放汇总数字（highlight）不算主次 |
| 一段实拍素材 | 整页视频 | 往上压字。画面亮部读不出来，要说话就用下一页 |
| 收尾 | 结尾页 | 一份稿子只有一个 |
| 收尾，要回顾整份稿子、感谢幕后成员 | 结尾页 · 回顾片尾（同款 `recipes/recap-credits`） | 一个人做的稿子（名单撑不起滚动）；可回顾的页少于 3 页 |
| 一页一张照片讲演变 | 故事稿（`story-mode.md`） | 混进汇报稿的页面类型 |

**按项数选**，凑数和砍数都会露馅：

| 项数 | 用 |
| --- | --- |
| 2 | 对比页 |
| 3–6（定性） | 列表页 |
| 4（有先后） | 横向时间线页 |
| 4–6（有量级、名字长） | 横向条形图页 |
| 4 + 一个主角 | Bento 基本格位 |
| 8 + 一个主角 | Bento 密集版 |
| 9（等权） | Bento 三栏版 |
| 10 以上 | 拆成两页。一页塞不下十条，塞进去字就小到读不出 |

**选完页面类型再看转场。** 页面类型决定这一页长什么样，
`transitions.md` 的「按关系选手法」决定它和上一页怎么接 —— 两件事分开想，
但有一个例外：**整页视频和匹配剪辑是绑定的**（视频末帧是静的，正好给下一页接住），
Bento 的格子天生带 `data-split` / `data-zoom` 锚点，接一变多和放大进元素内部最顺。

### 封面
- 标题 `.t-display`：水平居中，`top:400`
- 副标题 `.t-body`：`top:600`，`width:1200 text-align:center left:360`
- 装饰（`.s-accent` 横条或 `.s-dot`）：`top:680` 附近，水平居中

### 章节页
- `.t-body`「第 N 部分」：`left:120 top:360`
- `.t-display` 章节名：`left:120 top:440`

### 列表页（标题 + 面板 + 条目）
- 标题 `.t-h1`：`left:120 top:80`
- 面板 `.s-surface`：`left:120 top:240 width:1680 height:760`
- 条目：`left:200` 起。
  - 单行条目（只有 `.t-h2`）：第一行 `top:320`，行距 120，最多 6 行。
  - 双行条目（`.t-h2` + 下面一行 `.t-body`）：`.t-body` 在 `.t-h2` 下方 72，行距 200，最多 3 条。
- 条目右侧的数值 `.t-body`：`left:1360`，`top` 比同行 `.t-h2` 多 6。
- 高亮某一行：`.s-accent-soft`，`left:160 width:1600 height:120`，`top` 比 `.t-h2` 少 40。

### 数据页
- 标题 `.t-h1`：`left:120 top:80`
- 数字 `.t-metric`：`left:120 top:320`（宽度不超过 800）
- 数字说明 `.t-h2`：`left:120 top:680`；补充 `.t-body`：`left:120 top:760 width:800`
- 右侧面板 `.s-surface`：`left:1000 top:240 width:800 height:760`，里面可以放：
  - **柱状图**：面板里柱子可用宽度 640（`left:1080` 到 `1720`）。按根数取柱宽和间距：

    | 根数 | 柱宽 | 间距 | 各柱 `left` |
    | --- | --- | --- | --- |
    | 3 | 120 | 140 | 1080 / 1340 / 1600 |
    | 4 | 100 | 80 | 1080 / 1260 / 1440 / 1620 |
    | 5 | 80 | 60 | 1080 / 1220 / 1360 / 1500 / 1640 |

    底边对齐 `top+height = 880`，最高的柱高 440，其他按数据比例算。
    柱下标签 `.t-body`：`top:900`，`width` 等于柱宽加间距，居中在柱子下面。
    普通柱 `.s-surface-2`，重点柱 `.s-accent`。柱子写 `data-enter="grow-up"`，
    底部加一条坐标轴 `.s-accent`：`left:1040 width:720 height:4`，`top` 等于柱子底边。
  - **折线图**：一个 `<svg>`，`left:1040 top:320 width:720 height:480`，`viewBox="0 0 720 480"`（单位就是像素）。
    - 每条线一个 `<path>`，类用 `.l-accent`（重点线）`.l-surface` `.l-text`，最多 3 条。坐标在 viewBox 里按数据比例算。
    - 基线和参考线另放一个 `<svg>`（同位置同尺寸），用 `.l-dim`，不写 `data-enter="draw"`，先于折线出现。
    - 折线的 `<svg>` 写 `data-enter="draw"`，线的顺序就是画的顺序，重点线放最后。
    - 线尾的数值 `.t-body` 或主题的小标签放在线的终点右边 16px，在所有线画完后出（延迟 ≈ 折线延迟 + 0.15 × 条数 + 0.6）。
  - **排行**：`.t-h2` 名称 `left:1080`，数值 `.t-h2 .t-accent` `left:1600`，行距 120，第一行 `top:320`。
  - **一个徽章**：`.s-dot` 或暗橙圆，`width/height:320`，中心 `(1400, 560)`；名称 `.t-h2` 居中在 `top:760`。

### 对比页
- 标题 `.t-h1`：`left:120 top:80`
- 两个面板：`left:120` 和 `left:1000`，`top:240 width:800 height:760`
- 强调的一侧 `.s-accent-soft`，另一侧 `.s-surface`

### 横向条形图页

4 到 6 项排名或对比，**每项的名字都很长**（部门名、产品名、渠道名）时用它。
数据页里的柱状图是竖的，标签只能塞在窄柱下面；横条的名字占一整行左侧，长名字放得下。

| | 值 |
| --- | --- |
| 标题 `.t-h1` | `left:120 top:80` |
| 名称 `.t-h2` | `left:120 width:480`，`top` 比条少 4 |
| 条 | `left:680`，可用宽度 **880**（680 → 1560），高 **56** |
| 数值 `.t-h2 .t-accent` | `left:1600`，`top` 同名称 |
| 行距 | 120，第一行条 `top:240`，**最多 6 行** |

最长的条写满 880，其余按数据比例算，取整到 1px。普通条 `.s-surface`，重点条 `.s-accent`。
**条一律写 `data-enter="grow-right"`**，从左边长出来；延迟从 `0.9` 起，每行加 `0.08`。

**为转场预留**：最长的那条写 `data-id="axis"` —— 它和上一页的装饰横线、
或者横向时间线的轴是同一个形状族（都是细长横条），可以直接形态变换接上。

### 横向时间线页

多步骤流程或时间演化，4 个节点（理由见本节末「只放 4 站」）。和列表页的区别是**它断言了顺序**，
节点之间的距离就是过程本身；列表页的条目是无序的并列。

| | 值 |
| --- | --- |
| 标题 `.t-h1` | `left:120 top:80` |
| 轴 `.s-accent` | `left:120 top:560 width:1680 height:4` |
| 节点 `.s-dot` | `40×40`，`top:542`（圆心落在轴上）|
| 节点 `left` | `120 / 560 / 1000 / 1440` —— 和 Bento 的四列同一套 |
| 节点标题 `.t-h2` | `top:440`，`left` 对齐节点，`width:360` |
| 时间 `.t-body .t-dim` | `top:620`，同上 |
| 说明 `.t-body` | `top:680 width:360` |

**为转场预留**，锚点不要改名：

| 关系 | 手法 | 怎么写 |
| --- | --- | --- |
| 轴从上一页的装饰横线变来 | 形态变换 | 两页的横条都写 `data-id="axis"` |
| 同一条轴，换一组节点内容 | 元素交接 | 目标页 `data-st="carry"`；**轴和节点不写 `data-carry`**（前后一样，原地不动），只有标题、时间、说明写 |
| 钻进某个节点看细节 | 放大进元素内部 | 节点写 `data-zoom="node-2"` |

轴不动、只有内容沿轴流过去 —— 观众读到的是「沿着时间往前走」，
这是别的页面类型表达不了的关系。

**只放 4 站。** 标签宽 360、节点间距 440，第四站的标签正好落在 `1440–1800`，
再加一站就会挤到右边安全区外、或者压住前一站的说明。
超过 4 站就拆成两页（用元素交接接起来），或者改用列表页。

### Bento 网格页

一页并列五块，大小不等。**这是唯一允许一页有多个主角的页面类型**，代价是多了两条硬规则（见下）。
适合总览、参数墙、一组并列的佐证。版式片段在 `templates/layouts/bento.html`，坐标和锚点都写好了，整段复制。

卡片类型系统借自 [apple-bento-grid](https://github.com/hubeiqiao/apple-bento-grid)，坐标是本 skill 自己的 40 网格。

**格位**（4 列 × 2 行）

| | 值 |
| --- | --- |
| 列 `left` | 120 / 560 / 1000 / 1440，每列宽 360，横向间距 80 |
| 行 `top` | 240 / 640，每行高 360，纵向间距 40 |
| hero 格 | `left:120 top:240 width:800 height:760`（占左两列两行） |
| 四个小格 | `(1000,240) (1440,240) (1000,640) (1440,640)`，各 `360×360` |
| 页标题 `.t-h1` | `left:120 top:80` |

合并变体，用来填掉没内容的位置：竖长 `360×760`、横长 `800×360`、大方 `800×760`。

**另外两套格位**，来自 apple-bento-grid 的 Template A / B，按 1920×1080 和 40 网格重算：

| 名字 | 格位 | 块数 | 适合 |
| --- | --- | --- | --- |
| 基本（上表） | 4 列宽 360（间距 80）× 2 行高 360（间距 40），行 `240 / 640` | hero + 4 | 一个主角带四条佐证 |
| **密集版** | 同样 4 列 × **3 行高 240**（间距 40），行 `200 / 480 / 760`；hero 占左两列前两行 `800×520` | hero + 8 | 参数墙、总览，信息多 |
| **三栏版** | **3 列宽 480（间距 120）** × 3 行高 240，列 `120 / 720 / 1320`，行 `200 / 480 / 760` | 9（不设 hero） | 并列的九条，每条都同等重要 |

密集版和三栏版的**行高只有 240**，扣掉 40 留白只剩 160，所以**格内数字降到 `.t-h1`**（72），
标题用 `.t-h2`，说明用主题的小标签。`.t-display` 只有基本格位的 360 高格子放得下。
这两套格位的页标题放 `left:120 top:80`，第一行从 `top:200` 起。

**七种卡片类型**，每格选一种：

| 类型 | 放什么 | 用哪些类 |
| --- | --- | --- |
| `hero` | 标题 + 副题，只能放 hero 格 | `.t-display` + `.t-body` |
| `stat` | 一个大数字 + 说明 | `.t-display` + `.t-label` 或 `.t-body` |
| `category` | 分类标签 + 名称 + 说明 | `.t-label .t-dim` + `.t-h2` + `.t-body` |
| `chart` | 柱状图，占横长格或 hero 格 | `.s-accent` 柱 + 轴，写 `data-enter="grow-up"` |
| `badge` | 小标签 + 数字 | `.t-label` + `.t-display` |
| `quote` | 一句短引文 + 出处 | `.t-h2` + `.t-label` |
| `highlight` | 满格强调底 + 一个数字，一页最多一个 | **`.s-accent-soft`** 格 + `.t-display .t-on-accent` |

**highlight 格铺底只能用 `.s-accent-soft`，不要用 `.s-accent`。**
后者的圆角取自 `--radius-s`，在把 `--radius-s` 设成胶囊形的主题里（比如 Editorial Tri-Tone 的 999px）
会变成一颗药丸，把网格破掉。`.s-accent-soft` 取 `--radius-m`，和其他格子一致。

**格内留白 40**：内容从 `格.left + 40`、`格.top + 40` 起，宽度不超过 `格.width − 80`。

**小格里的字号上限是 `.t-display`，而且最多 3 个字符**（360 宽减去留白只剩 280，`.t-display` 一个字约 88px）。
更长的数字降到 `.t-h1`。`.t-metric` 只能放 hero 格，最多 4 个字符。

#### 两条硬规则

**1. 五个位置必须全部填满**（借自 apple-bento-grid 的「零空格」）。
内容不够就用合并变体把相邻格并成一格，不许留空位。
空位会让「整组归位」和「一变多」在中途露出洞。

**2. 五个位置的卡片类型至少要有三种不同。**
四个同构的方块是 bento grid 最常见的失败，观众看到的是一堵墙，不是一份 bento。
层级靠**类型差异和跨度**做，不是靠每格换底色 —— 所以强调色仍然守 15% 上限，
一页最多一个 `highlight` 格用 `.s-accent-soft` 铺底，其余格只用 `.s-surface` / `.s-surface-2`。

#### 为转场预留

片段里的锚点不要改名，改了下面这些就接不上：

| 关系 | 手法 | 怎么写 |
| --- | --- | --- |
| 下一页还是 bento，内容换了 | 元素交接 | 目标页 `data-st="carry"`，格子不写 `data-carry`（原地不动），只有文字写 |
| hero 格撑满成下一页底色 | 形态变换 | 目标页整页形状写 `data-id="hero"`，见「整页 ↔ 卡片」 |
| 某一格是下一页的细节 | 放大进元素内部 | 目标页 `data-st="zoom-into" data-st-direction="in" data-st-from="cell-2"` |
| 上一页一张总卡裂成四格 | 一变多 | 目标页 `data-st="split" data-st-split="cells"` |
| 四格收成下一页一张卡 | 多合一 | 目标页 `data-st="merge" data-st-merge="cells"` |

一变多 / 多合一仍然受「只在同色系里变」限制：四个小格的颜色类要和那张总卡同色系。

### 整页视频

一页只放一段视频，铺满画布。用来引一段实拍素材，或者把别处录好的片段放进稿子里。

```html
<section>
  <video class="v-full" src="../clips/apple-15s.mp4" muted playsinline></video>
</section>
```

1. **素材先转成和稿子一样的帧率和画幅**（1920×1080 @30fps），否则录出来会抖：
   `ffmpeg -ss <起> -to <止> -i <源> -vf "scale=1920:1080,fps=30" -c:v libx264 -crf 18 -an <出>.mp4`
2. 放映时翻到这一页自动从头播（转场放完才开始），离开就停。视频一律静音 —— 声音在剪辑里配。
3. 录制时 `capture.mjs` 不靠真实播放，而是按毫秒 seek 视频、等 `seeked` 再截图，所以每帧确定。
   这一页的停留时长自动取视频长度，`data-hold` 写得更长才会在末帧多定格一会儿。
4. **视频页不要再写别的内容。** 压在视频上的字在画面亮部读不出来，要说话就用下一页。
   唯一的例外是隐形锚（见下）。
5. 视频页也能当转场的上一页。最好用的是匹配剪辑：切走的时候画面是静的（末帧），
   下一页把那个形状接住。

#### 隐形锚（视频画面里的形状）

匹配剪辑的锚要是 DOM 元素，但视频里那个形状只是像素。用一个看不见的框把它标出来：

```html
<video class="v-full" src="../clips/apple-15s.mp4" muted playsinline></video>
<div data-match="pill" class="s-anchor" style="left:730px; top:386px; width:744px; height:324px;"></div>
```

框的位置和大小**从末帧上量**，别估。取一张末帧 PNG，按颜色框出那个形状的外接框：

```bash
ffmpeg -sseof -0.1 -i clip.mp4 -frames:v 1 last.png
```

`.s-anchor` 只是 `opacity: 0`，观众看不到；它不参与圆角校验（它本来就没有轮廓），
中心和尺寸照常校验。

### 结尾页
- `.t-display`：水平居中，`top:400`
- 一行 `.t-body`：`top:600`，`width:1200 text-align:center left:360`
- 用了数据时，出处写成一到两行 `.t-label`：`left:120 top:920` 起，行距 40（`data.md`「写出处」）

### 结尾页 · 回顾片尾
- 底：整页 `.s-surface`（`left:0 top:0 width:1920 height:1080 border-radius:0`），写在屏幕前面
- 屏幕 `.s-recap`：`left:120 top:220 width:1120 height:630`（16:9）
- 名单 `.t-credits`：`left:1320 top:120 width:480 height:840`，行高 80。压在 `.s-surface` 上加 `.t-on-surface`
- 名单条目写 `<li><span>职责</span><b>姓名</b></li>`，不许加别的结构

## 为转场预留

- 做共享元素的元素，前后两页都用上面的标准位置，不要自己发明中间位置。
- 做元素交接的两页，用同一种页面类型（数据页 → 数据页）。
- 做匹配放大的两个元素，先定中心点，再算 `left = cx − width/2`。
