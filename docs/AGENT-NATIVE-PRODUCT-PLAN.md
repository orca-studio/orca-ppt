# Agent Native PPT 产品实施计划

目标：从已有材料出发，共同完成叙事、成稿、评审、排练和交付。人可以直接做小改动，Agent 可以基于同一份实时状态完成跨页修改；每一步可检查、可撤销。

| 顺序 | 产品能力       | 实施范围                                                             | 验收标准                                           | 状态                                 |
| ---- | -------------- | -------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| 0    | 共享画布上下文 | 当前页、选区、元素几何、运行时错误、版本绑定截图；共享协议和原生 MCP | Agent 读取人与画布同一页、同一版本；过期目标拒绝   | 已实施                               |
| 1A   | 基础页面编辑   | 添加空白页、删除、移动；同步大纲与转场；共享撤销/重做                | UI 和 MCP 同一操作；源码字节保留；不覆盖外部改动   | 已实施                               |
| 1B   | 图片编辑       | 替换 deck 内已有图片引用；随后增加系统选图、导入资源、常用样式       | 选区、页号和版本共同定位；资源随 deck 迁移；可撤销 | 已完成已有资源替换；导入与样式待实施 |
| 2    | 任务评审       | 任务级变更摘要、受影响页面、前后对比、接受和整组撤销                 | 用户能判断一次任务改了什么，选择保留或还原         | 待实施                               |
| 3    | 内容与叙事     | 材料入口、故事板、每页主张与证据、引用、内容锁定                     | Agent 修改保留用户确认的事实；来源可追溯           | 待实施                               |
| 4    | 排练           | 离屏转场检查、讲稿、时间预算、排练反馈                               | 检查真实过渡过程；导出可执行的讲述顺序             | 待实施                               |
| 5    | 交付           | HTML/PDF、图片与资源检查；明确 PPTX 的编辑性与动画兼容范围           | 无缺失资源；交付前有格式预览和差异说明             | 待实施                               |

## 第一批边界

先建立共享编辑基础，不引入新的 Agent 运行时。Jevbot、其他 MCP 客户端和应用 UI 调用同一组 contracts/server 操作；WebMCP 待 Electron 的实际支持和宿主发现链路验证后再作为适配入口。

页面添加先提供标题空白页。图片替换先接受 deck 内已有的相对资源路径以及具有简单 id/data-anchor 的图片；文件选取与资源导入单独实施。样式编辑尚未实施。

结构修改绑定 expectedRevision，并同步现有 brief 页数、outline 页序和仍然相邻的 transition pair。不替用户编造新增页的版式理由或转场关系；新增页面的大纲标记为待补充。修改前后内容进入同一条内存历史，进程重启后历史不保留。结构和图片修改后的 HTML 或关联元数据被外部修改时，撤销拒绝，避免覆盖外部结果。

不在第一批承诺：完整 PPTX 编辑器、自动审美判定、持久历史、外部文件写入的自动撤销、整个 deck 的跨文件原子提交。

## 第一批验证

自动检查：typecheck、全量测试、Prettier lint、生产构建。桌面与原生 MCP 联调使用临时稿子，验证 UI 添加/移动/删除，MCP 撤销 UI 的三步修改并字节还原，MCP 新增/移动/撤销与旧版本拒绝，图片替换后实时资源地址与版本绑定截图，以及 UI 换图/撤销。修复重载时第 0 页恢复被跳过的问题。稿子变动会清除旧缩略图并请求重新生成，迟到的旧请求不覆盖新结果。
