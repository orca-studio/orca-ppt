# Vision

## 问题

做演示稿这件事,今天被切成了两半,中间那道缝没人补。

**一半是「写」。** Agent 已经能写出不错的 HTML 稿子 —— `orca-transition-skill` 这类
skill 把转场规范、主题、版式都给足了,模型照着做,出来的东西能看。但这一半发生在终端
里:你说一句、它写一版、你自己开浏览器翻一遍、再回终端描述哪里不对。**问题不在模型,
在于你必须用文字描述一个视觉对象。** 「第四页那个标题」「转场太快了」—— 你在给一个看
不见你屏幕的人打电话。

**另一半是「看」。** Keynote、Figma Slides、Gamma 都很好看,都能所见即所得,但它们里面
没有 agent,或者只有一个被产品包死的、你换不掉也调不动的 agent。你付费的 Claude Max、
ChatGPT Plus 在这些产品里一分钱用不上。

两半之间的缝是:**演示稿是一个必须被放映才能评判的对象,而 agent 工作流里没有放映这一
步。** 转场对不对,只有翻页的那 600 毫秒能回答;一页挤不挤,只有 1920×1080 满屏能回答。
截图回答不了,文字更回答不了。

## 产品

**orca-pptcode 是一个演示稿工作台,agent 是它的引擎,不是它的界面。**

一个窗口里:左边是大纲和页胶片,中间是**真在跑的那份 deck**(不是截图,是 reveal.js +
GSAP 在放),右边是对话。你在中间那块画布上点中一个标题,说「这儿太挤」,这条意见带着
页号、选择器和一张裁切图一起进对话 —— agent 拿到的是坐标,不是形容词。

引擎是你自己机器上装的 agent、你自己的订阅。我们不转售 token,不代理你的凭证。

## 和 TasteCode 的关系

TasteCode 证明了这个形状:本地 server 拥有全部状态与编排,适配器驱动各家官方 CLI,渲染
层是薄客户端;真正的差异化是上面那个垂直 Mode。orca-pptcode 借它的骨架,换一个垂直领域,
**并且不和它竞争** —— 它做通用 coding agent 客户端,我们做演示稿这一件事。

具体地:worktree、PR 审查、diff review、多项目管理,我们一概不做。省下来的力气全部投进
下面四件它不会做的事。

## 四个赌注

### 1. 画布即评审面

预览是真在放的 deck。点元素 → 生成锚(页号 + CSS 选择器 + 裁切图)→ 直接成为给 agent 的
一条带坐标的指令。这是本产品存在的理由,其余三件都是它的配套。

### 2. 转场是一等公民

skill 里那份「每次翻页一行:两页的关系 + 选用的手法」的转场计划,在这里是一条可视时间轴。
改一个手法只重录那一段,不重录整片。没有别的产品把「翻页之间」当成可编辑对象。

### 3. 录制与导出内建

`capture.mjs` 逐帧 seek 出 mp4 这套东西,变成 server 的一个 job。用户不碰命令行,拿到的是
mp4 / PDF / pptx。

### 4. 自检回路

录完自动跑帧差量和 `transitions.md` 末尾那套自检标准,不合格自己修,修不动才找人。对应
Design Mode 的 render → critique → revise,只是我们的 render 是一段视频而不是一张截图。

## 成功长什么样

- **v0(自用)**:做自己的稿子不再开终端。
- **v1(公开 beta)**:一个装了 Claude Code 的人,说一句话、点几下、导出一段 mp4,全程不碰
  命令行,成品质量和现在手工跑 skill 一样好。
- **v2**:「用 AI 做演示稿」的默认答案。不是因为模型更强,是因为只有这里能放映、能点、能录。

## 非目标

- 不做模型,不做微调。
- 不做通用 coding agent 客户端 —— 那是 TasteCode,我们不重复。
- 不转售推理,不代理凭证。
- 不做云端渲染农场。本地优先,云是可选项且靠后。
- 不做 Keynote 的替代品。我们的产物是 HTML deck 和视频,不是 .key。
