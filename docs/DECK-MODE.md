# Deck Mode

产品的垂直闭环。这份文档是实现指南:阶段划分、产物契约、检视锚的格式、自检标准。

## 目标体验

1. 用户开一份新 deck,选主题和风格锚(或者不选,让它挑并记下假设)。
2. 说一句话:「讲讲我们 Q3 的增长,给投资人看,五分钟」。
3. 阶段推进,每一步的产物都能在左栏展开看:brief → theme → outline → plan → build。
4. deck 在中间画布上**开始放映**。
5. 用户翻页、点元素、提意见。每条意见带锚,挂进待办队列。
6. 跟 agent 说一声,它取走、改,画布热更新,只重放受影响的那几页。
7. 录制,自检把可疑的地方标出来,导出。

## 阶段与产物

每个阶段落一个 JSON 到 `.deck/`,都是可检视、可重放、可手改的。

| 阶段    | 产物                    | 内容                                                              |
| ------- | ----------------------- | ----------------------------------------------------------------- |
| Brief   | `.deck/brief.json`      | 主题、受众、语气、页数、时长、模式(汇报稿/故事稿)、记录下来的假设 |
| Theme   | `.deck/theme.json`      | 选中的主题名或新建主题的 token 表                                 |
| Outline | `.deck/outline.json`    | 每页一条:主角、内容要点、选中的版式,以及**为什么是这个版式**      |
| Plan    | `.deck/plan.json`       | 转场计划,每次翻页一行:`{ from, to, relation, technique, anchor }` |
| Build   | `deck.html` + `assets/` | 成品                                                              |
| Review  | `.deck/review/*.json`   | 录制帧证据、帧差量、确定性检查判定与产出的锚                      |

**Brief 阶段不提问。** 缺的细节自己定,把假设写进 brief,用户在左栏看得见、能改。一上来问
五个问题的产品没人用第二次。

**Outline 必须写出选版式的理由。** `visual-spec.md` 里那张表有一列「严禁用」—— 没有大小关系
的东西进图表、不对等的两项并排、凑不满的格子硬撑。理由字段让这条规则可被检查,而不是只
写在文档里没人执行。

## 检视锚

本产品的核心数据结构。用户在画布上点中一个元素时,渲染层生成:

```jsonc
{
  "slide": 4, // 页号
  "selector": "section:nth-child(4) > h2",
  "box": { "x": 180, "y": 220, "w": 1560, "h": 120 }, // 1920×1080 坐标系
  "crop": "<应用数据目录>/anchors/8f3a.png", // 带上下文的裁切图
  "text": "增长的三个来源", // 元素当前文本,便于 agent 定位
  "note": "这儿太挤", // 用户说的话
}
```

锚挂进待办队列,agent 调 `take_requests` 取走 —— 它拿到的是坐标而不是形容词。这是整个产品
相对「终端里跑 skill」的唯一实质性优势,所有其他功能都是它的配套。

裁切图存在**应用自己的数据目录**,不进 deck 目录:它是这一次评审的临时证据,不是稿子的内容,
而且写进 deck 会让文件监听把它当成稿子变了 —— 取一次锚就刷一次画布。`.deck/review/` 留给
自检那些该跟着稿子走的逐帧证据。

文字描述永远带上,图只是额外证据:引擎不吃图、或者根本没截到,锚本身仍然成立。

**锚也用在转场上**:时间轴上选中一段翻页,锚变成 `{ from: 3, to: 4, technique: "match-cut" }`,
意见是「这个硬切没对上」。

## 转场时间轴

`plan.json` 的可视化。一行一次翻页:

```
 3 → 4   共享元素     标题从副位升为主位
 4 → 5   形态变换     圆形指标盘 → 柱状图
 5 → 6   匹配剪辑     ⚠ 锚轮廓未重合
```

选中一行可以:改手法、只重录这一段、看这一段的逐帧。**只重录一段**是这里的关键 —— 一份
20 页的稿子整片重录要几分钟,改一个手法就重跑全片会让迭代死掉。

## 自检回路

录完自动跑,对应 Design Mode 的 render → critique → revise,区别是我们的 render 是一段视频,
**而且 critique 归人**。演示稿哪里不对,人一眼就能判 —— 不像设计工具那样值得让模型代劳。
所以这一节只做两件事:**确定性地找出可疑的地方,然后让它一点就能变成指令。**

三项检查全在 server,不用模型:

1. **页面自报问题**:`capture.mjs` 输出末尾的「页面报告的问题」必须为空。
2. **帧差量运动**:每次转场里,画面变化明显的帧应连续占满转场区间的大部分,而不是集中在
   一两帧。集中 = 转场没真的动,是个跳变。
3. **匹配剪辑走单独一条**:它是硬切,没有转场帧,第 2 条不适用。验法是取切点前后两帧,确认
   锚的轮廓完全重合、而画面上其余东西都换了。

### 不合格产出的是锚,不是报告

这是这一节唯一要紧的设计:**自检的产出和人在画布上点出来的是同一个结构。**

| 检查               | 产出                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| 页面自报问题       | 页级锚 `{ slide, note: 原始报错 }`                                              |
| 帧差量集中         | 转场锚 `{ from, to, technique, note: "转场没真的动,变化集中在 2 帧" }`,附证据帧 |
| 匹配剪辑轮廓未重合 | 转场锚,附切点前后两帧                                                           |

于是「标出来」和「挂进待办队列」是同一条路径:**时间轴上那一行黄的、页胶片上那个角标,
点一下就进队列**,人不用把同一个问题再用文字描述一遍。agent 那头 `take_requests` 收到的
格式和人点出来的完全一样,不用加新工具。

反过来说:如果标黄只是个颜色、人看见之后还得回画布上重新取一次锚,那这轮自检等于白做。

**「critique 归人」说的是这条自动回路,不是「模型不看画面」。** agent 在自己的回合里随时
可以调 `capture_slide` 截一页来看 —— 那是同步的、它自己发起的,和这里说的「录完几分钟后
没人在那头等着被推送」是两件事。别把这一节读成「模型不参与视觉判断」。

**还没解决:页级锚在契约里没有位置。** 现在 `Anchor` 只有 `element` 和 `transition` 两种,
而 `InspectAnchor` 强制要 `selector` 和 `box` —— 上表里那条「页级锚 `{ slide, note }`」塞
不进去。M5 落地前要么加一个 `kind: 'slide'` 变体,要么「同一个结构、不用加新工具」这句话
就不成立。

证据帧跟着稿子走,落 `.deck/review/`(和检视锚的裁切图不同 —— 那个是临时证据,落应用数据
目录)。

_不做:_ **自动视觉自评**(抽关键帧调模型打分)和**自动修复轮次**。agent 需要看画面时自己
调 `capture_slide`,那是它回合内的事;录制是几分钟的异步 job,跑完时发起它的那个回合多半
已经结束了,没有谁在那头等着被推送。判不了的如实标出来,交给人。

## 与 skill 的关系

`orca-ppt-skill` 和 `orca-motion-skill` 不被抄进本仓,而是作为**内容层依赖**被读取:
规范文档、主题、版式模板、`capture.mjs` 都从 skill 目录读。skill 更新,产品跟着更新,不用
两边同步。

产品负责的是 skill 做不到的那部分:把规范变成界面,把放映变成可点击的评审面,把录制变成
一个按钮。

_否掉:_ 把规范内容复制进 `packages/deck-agent`(立刻和 skill 分叉,两边都不对)。
